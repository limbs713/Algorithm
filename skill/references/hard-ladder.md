# Hard 해부 — 무엇이 Hard를 Hard로 만드는가

사용자가 Hard에서 반복해 무너질 때, 또는 Hard를 처음 배정하기 전에 읽는다. 목표는 "Hard 문제 목록을 외우는 것"이 아니라 **Hard가 어려워지는 방식이 몇 가지 안 된다는 걸 체감시키는 것**이다.

## Hard가 어려워지는 5가지 방식

LeetCode Hard의 거의 전부가 아래 다섯 중 하나(혹은 둘의 조합)다. 사용자가 막혔을 때 "이 문제는 몇 번 유형인가"를 먼저 묻는 것만으로도 방향이 잡히는 경우가 많다.

### 유형 A — 패턴 합성
Medium 패턴 두 개를 겹쳐 놓았다. 부품은 이미 다 아는 것이라, 알아보기만 하면 난이도가 급락한다.

| 문제 | = | 부품 1 | + | 부품 2 |
|------|---|--------|---|--------|
| 239 Sliding Window Maximum | | 슬라이딩 윈도우 | | 단조 덱 |
| 862 Shortest Subarray ≥ K | | 누적합 | | 단조 덱 |
| 212 Word Search II | | 백트래킹 | | 트라이 |
| 218 Skyline | | 구간 스윕 | | 힙 |
| 85 Maximal Rectangle | | 행별 히스토그램 | | 단조 스택 |
| 315 Count of Smaller After Self | | 좌표 압축 | | 펜윅 트리 |
| 778 Swim in Rising Water | | 다익스트라 | | max 완화 |

**훈련법** — 합성형에서 막히면 H2 힌트를 "부품 하나"만 준다. "슬라이딩 윈도우인 건 맞습니다. 그런데 윈도우 안의 최댓값을 O(1)로 얻으려면?" 나머지 절반은 사용자가 찾게 둔다.

### 유형 B — 비자명한 관찰 하나
알고리즘은 평범한데, 어떤 사실을 알아채야만 성립한다. 이게 진짜 Hard의 본체이고, 통찰 카드로 남길 가치가 가장 큰 유형이다.

- **424** — `maxCount`를 감소시키지 않아도 된다. 답은 커질 때만 갱신되므로.
- **312 Burst Balloons** — "먼저 터뜨릴 것"이 아니라 "**마지막에 남을 것**"으로 뒤집으면 좌우가 독립이 된다.
- **124 Binary Tree Max Path Sum** — 부모에게 반환하는 값과 답 후보가 **다르다**.
- **803 Bricks Falling** — 유니온 파인드는 분리를 못 하므로 **시간을 거꾸로** 돌린다.
- **4 Median of Two Sorted Arrays** — 병합하지 말고 **파티션 위치**를 이분탐색한다.
- **992 Subarrays with K Distinct** — "정확히 k" = `atMost(k) - atMost(k-1)`.
- **871 Refueling Stops** — 지나온 주유소를 힙에 쌓아두고, 막히면 **과거 선택을 뒤늦게 취소**한다.

**훈련법** — 이 유형은 힌트를 줄 때 관찰을 그대로 말하면 안 된다. 관찰이 필요한 **지점을 가리키는 질문**으로 바꾼다. 312라면 "먼저 터뜨릴 걸 고르면 왜 상태가 안 닫히죠?"

### 유형 C — 상태 설계
DP인 건 명백한데, 상태에 차원을 하나 더 얹어야 한다.

- 546 Remove Boxes — `dp[i][j][k]`, k = 왼쪽에 붙어 있는 같은 색 개수
- 887 Super Egg Drop — 상태를 뒤집는다: "층수 → 시도 횟수"가 아니라 "시도 횟수 → 커버 가능한 층수"
- 1349 계열 비트마스크 DP — 이전 행의 배치를 비트로

**신호** — 자연스러운 2차원 상태로 짰는데 전이가 안 닫히면(같은 상태에서 서로 다른 답이 나오면) 차원이 부족한 것이다.

### 유형 D — 구현 폭발
발상은 쉬운데 코드가 길고 케이스가 많다. 10, 44, 37, 297 같은 것들.

**훈련법** — 여기서는 힌트보다 **케이스 표를 먼저 종이에 적게** 하는 게 낫다. 코드를 치기 전에 `*`가 0개 매칭 / 1개 이상 매칭 두 갈래를 표로 적으면 구현은 기계적으로 따라온다. 사용자가 표 없이 바로 치기 시작하면 말린다.

### 유형 E — 자료구조 지식
알면 풀고 모르면 못 푼다. 펜윅/세그먼트 트리, LFU의 이중 버킷 구조 등.

**훈련법** — 이건 회상 훈련이 아니라 학습이다. 모르면 H4까지 빠르게 내려가서 구조를 익히게 하고, 대신 **같은 구조를 쓰는 다른 문제를 3일 뒤에 배정**한다.

## 승급 경로

한 패턴에서 Medium을 **힌트 H2 이하로 2개** 풀었으면 그 패턴의 Hard로 올린다. `lc.py today`가 이 규칙으로 자동 배정한다.

기반 없이 Hard만 파면 패턴이 안 붙고, Medium만 무한히 돌면 합성을 볼 기회가 없다. 둘 다 실패 모드다.

권장 순서 (앞쪽이 합성의 부품으로 더 자주 쓰인다):

```
슬라이딩 윈도우 → 투 포인터 → 이분 탐색(답 탐색까지) → 누적합
  → 단조 스택 → 단조 덱 → 힙 → 그래프 BFS/DFS → 위상 정렬
  → 유니온 파인드 → 최단 경로 → 1차원 DP → 2차원 DP
  → 백트래킹(+트라이) → 구간 DP → 트리 → 그리디 → 펜윅 트리
```

단조 덱과 트라이는 단독으로 나오는 일이 드물고 거의 항상 합성의 부품이다. 그래서 이 둘은 Medium 단계를 짧게 지나가고 바로 합성 Hard로 붙이는 게 효율적이다.

## "아이디어가 안 떠오른다"고 할 때의 진단

사용자가 막혔다고 할 때 어디서 막혔는지를 먼저 특정한다. 층이 다르면 처방이 완전히 다르다.

| 증상 | 실제 문제 | 처방 |
|------|----------|------|
| 복잡도 목표를 못 말함 | 1단계 신호 읽기 미숙 | 매 세션 복잡도 역추론을 소리 내 하게 한다 |
| 패턴 후보가 안 떠오름 | 신호-패턴 연결이 약함 | `patterns.md`의 신호 절만 복습 카드로 만든다 |
| 패턴은 아는데 적용이 안 됨 | 템플릿 암기, 원리 미이해 | "왜 이 자료구조여야 하는가"를 말하게 한다 |
| 부품은 보이는데 합성이 안 됨 | 유형 A 경험 부족 | 합성 표의 문제를 연속 배정 |
| 다 맞는데 관찰 하나를 못 봄 | 유형 B, 정상 | 이게 원래 어려운 것. 카드로 남기고 넘어간다 |
| 발상은 되는데 구현이 무너짐 | 유형 D | 케이스 표를 먼저 쓰게 한다 |

마지막 줄이 중요하다. **유형 B에서 막히는 건 실력 부족이 아니라 정상이다.** 그 관찰은 원래 처음 보면 안 떠오르는 것이고, 그래서 카드로 남겨 3주 뒤에 되살리는 것이다. 사용자가 여기서 자책하면 이걸 짚어준다 — Hard를 즉발로 푸는 사람들도 그 관찰을 그 자리에서 발명한 게 아니라 예전에 본 것을 회상하는 것이다.
